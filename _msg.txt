Employee My Assets, and fix the detail panel and a translation bug

/my-assets shows the equipment currently assigned to the signed-in user: tag,
category, model, serial, assignment date and warranty. Read only, deliberately -
assign, return and retire are HR actions, and offering them here would be wrong
twice over: the employee is not the custodian of the company's reissue decision,
and the server derives status from rows only the service may write.

Reachable by STAFF as well as employees, which is the one deliberate difference
from /my-letters beside it. A sub-admin who is also on the roster has been handed
a laptop like anyone else, and is the person most likely to be mid-way through
logging its serial number. Someone with no employee record gets an empty list,
which is the right answer rather than a 403.

MY ASSET IS A DISTINCT TYPE from Asset, narrower by design, so the compiler
objects if someone copies a cost column across, rather than the code being right
by luck.

THE DETAIL PANEL WAS THE WRONG PRIMITIVE. It was built on Drawer, which is vaul -
a MOBILE BOTTOM SHEET that ignores width classes and slides up from the bottom
edge, so on a narrow viewport the panel was clipped off-screen with no reachable
close control. Switched to Sheet, the Radix side-panel primitive: fixed
inset-y-0 right-0, a dimmed backdrop, and a close button in its own top-right
corner, at max-w-lg because the custody history rows are two-column. Scrolling
now happens inside the panel rather than the page behind it.

Sheet's close button had a hardcoded English sr-only label. It is the only
dismiss affordance for anyone not using a pointer, so it is translated now.

Closing the panel no longer refreshes the table. Closing is not a mutation, and
doing so made the list flicker every time someone glanced at an asset.

THE TRANSLATION BUG WAS A HOUSE-CONVENTION MISTAKE, not a missing key. i18next
interpolates with DOUBLE braces, {{name}}. Single-brace {name} is ICU message
syntax, which i18next parses for plural/select and then leaves untouched, so the
template rendered literally as Delete "{name}"?. The key existed in both locale
files and parity was 100%, so the audit, the type checker and the unit tests were
all blind to it - only a person reading the dialog could see it.

assets.months was additionally the ONLY key in all 1069 using ICU plural syntax,
and it rendered as a bare "5" because no plural resolver is configured. Converted
to the {{count}} month(s) style the rest of the app already uses.

i18nInterpolation.test.ts now scans BOTH locale files for single-brace
placeholders, unbalanced braces and ICU plurals, so the whole class is caught
rather than the one key. assetsUi.test.ts pins the panel primitive, the close
affordance, and the read-only nature of the employee page; verified it fails when
the vaul Drawer is put back.

12 files / 342 tests.
